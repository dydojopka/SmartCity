# vaNYA

## Как работать

Тебе предоставлен готовый технический каркас. Не меняй `docker-compose.yml`,
общий формат JWT и `docs/API_CONTRACT.md` самостоятельно.

Перед началом запусти проект и прочитай `../docs/API_CONTRACT.md`.

## Задача 1. Notification Service

Рабочий каталог: `../services/notification-service/`.

Реализуй `POST /notifications`:

1. Проверь заголовок `X-Service-Token`.
2. При неверном токене верни `401`.
3. Сохрани уведомление в таблицу `notifications` со статусом `PENDING`.
4. Запиши имитацию отправки в лог.
5. Измени статус на `SENT` и верни созданное уведомление с кодом `201`.
6. Не записывай служебный токен в лог.

Добавь тест успешного запроса и тест неверного токена.

## Задача 2. Environment Service

Рабочий каталог: `../services/environment-service/`.

Реализуй:

- `GET /sensors` - список датчиков;
- `GET /sensors/{id}/data` - показания датчика;
- `POST /sensors/data` - новое показание.

Порядок:

1. Создай таблицы `sensors` и `sensor_readings`.
2. Добавь два тестовых датчика через seed.
3. Для POST проверь заголовок `X-Sensor-Key`.
4. Проверь, что датчик существует и имеет статус `ACTIVE`.
5. Сохрани значение и время измерения.
6. Обнови `last_seen_at`.
7. Для неизвестного датчика верни `404`, для неверного ключа - `401`.
8. Добавь тест успешного показания и тест неверного ключа.

## Задача 3. Frontend-страницы

Рабочий каталог: `../frontend/src/features/`.

После того как zheNYA подготовит маршрутизацию и авторизацию, добавь:

- список пользователей;
- список транспорта;
- парковки и кнопку «Забронировать»;
- форму и список заявок ЖКХ;
- список датчиков и просмотр показаний;
- список счетов и кнопку создания платежа.

На каждой странице должны быть:

- сообщение во время загрузки;
- понятное сообщение об ошибке;
- сообщение при пустом списке;
- обновление данных после успешного действия.

Используй `../frontend/src/api.js`, не добавляй Axios или другие библиотеки(на крайний случай спроси). Координаты показывай таблицей, карту делать не нужно.

- оба сервиса реализуют обязательные endpoints;
- неверные служебные ключи отклоняются;
- данные сохраняются только в собственной БД сервиса;
- тесты проходят;
- frontend вызывает API через готовый клиент;
- схемы БД соответствуют моделям.
