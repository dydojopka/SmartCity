# zheNYA

## Твоя зона ответственности

Ты отвечаешь за техническую основу проекта, авторизацию, Utility Service,
интеграцию и итоговую сдачу.

## Перед началом

1. Прочитай `../docs/API_CONTRACT.md`.
2. Запиши фамилии команды в `../README.md`.
3. Зафиксируй общие тестовые UUID пользователя, оператора и администратора.

## Задача 1. Identity Service

Рабочий каталог: `../services/identity-service/`.

Реализуй:

- `POST /auth/register`;
- `POST /auth/login`;
- `GET /users/me`;
- `GET /users/{id}`;
- `GET /users`.

Обязательно:

- уникальный email;
- Argon2-хеш пароля;
- JWT с `sub`, `role`, `exp`;
- пароль и `password_hash` никогда не возвращаются;
- логируются регистрация и вход без секретных данных;
- создаются тестовые пользователи `USER`, `OPERATOR`, `ADMIN`;
- есть тесты регистрации, повторного email, входа и доступа без JWT.

## Задача 2. Utility Service

Рабочий каталог: `../services/utility-service/`.

Реализуй:

- `POST /issues` — пользователь создаёт заявку от своего имени;
- `GET /issues` — пользователь видит свои заявки, оператор и администратор все;
- `PUT /issues/{id}` — статус меняет только оператор или администратор.

После изменения статуса отправляй `POST /notifications` по HTTP. Если сервис
уведомлений недоступен, запиши ошибку в лог, но не отменяй уже выполненное
изменение заявки.

## Задача 3. Frontend-основа

Рабочий каталог: `../frontend/src/`.

Нужно:

- настроить маршруты;
- сделать страницы регистрации, входа и профиля;
- использовать функции из `api.js`;
- сохранять JWT через `setToken`;
- перенаправлять неавторизованного пользователя на вход;
- подготовить общий layout и навигацию для страниц участника C.

## Задача 4. Интеграция

- поддерживай `docker-compose.yml` и `.env.example`;
- принимай pull request участников B и C;
- не меняй их предметный код без обсуждения;
- собери схемы БД в ZIP;
- выполни smoke-тест из `../../PLAN.md`;
- дополни итоговый README инструкцией запуска и примерами запросов.

## Готово, если

- Identity и Utility реализуют контракт;
- их тесты проходят;
- авторизация работает из браузера;
- весь проект запускается через `docker compose up --build`;
- все обязательные endpoints команды видны в Swagger;
- README содержит фамилии и вклад участников.
